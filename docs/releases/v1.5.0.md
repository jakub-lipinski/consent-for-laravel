# v1.5.0 - Livewire and more languages

This release adds **optional Livewire 3/4 support**, including component updates, `wire:navigate`, and interface language changes, plus complete **Czech and Dutch translations**. The package keeps its existing Blade components and browser API. **Saved preferences and their original expiry remain compatible** when policy, services, and consent settings are unchanged.

## Added

- Livewire integration for class-based, single-file, and multi-file components, navigation, redirects, and browser history. Supported baselines are **Livewire 3.8.10+ and 4.4.7+**, with the existing PHP 8.3+ and Laravel 12-13 requirements. Livewire is detected from the application and remains an optional dependency.
- Language updates for the complete banner/dialog and its paired signed audit notice after navigation or component locale changes. Accessible names, status/error messages, category purposes, and service descriptions follow the selected locale without saving a decision or extending its lifetime.
- Protection against Livewire 4 extracting gated single-file scripts before Blade compilation, including unindented tags. Consent templates receive stable Livewire keys while retaining the ordinary inert script transport.
- Optional `livewire.enabled` and `livewire.navigation` settings, with backward-compatible defaults of `true` and `auto`. Applications can select full visits with `reload` or disable special navigation/UI coordination without disabling generic script gating.
- A `consent:navigated` document event carrying `{ id, url, title, previousUrl }` once per completed compatible page swap. Initial load, prefetch, canceled visits, ordinary component morphs, and hash-only changes without a swap emit no event. **The adapter sends no automatic SPA measurements.**
- Complete Czech (`cs`) and Dutch (`nl`) dictionaries, bringing the bundled interface to **nine languages**. Both variants include preset purposes, accessible labels, status/error messages, the Advanced Google notice, and audit snapshots, with regional and custom fallback.
- A dedicated Livewire reference in the existing `consent-for-laravel-development` skill. Laravel Boost keeps one skill with thirteen focused references, including practical configuration, script, measurement, CSP, and upgrade examples.

## Changed

- New script activations pause during Livewire page swaps. Preserved unchanged blocks resume in order after navigation and cleanup; detached blocks cannot start their remaining scripts. Identical logical blocks and SDKs remain deduplicated for the document.
- Ordinary morphs with unchanged presentation preserve the preferences draft. A real navigation closes the dialog without saving its draft or returning focus to the departing page. Intentional language replacement updates the protected UI/notice container and restores the saved selection.
- A head marker compares runtime configuration and asset revisions before activating destination blocks. Changed configuration, changed assets, or missing/conflicting markers require bounded fresh-document recovery. Nonce-bearing Livewire 3 or unknown-major runtimes use full visits in auto mode.
- Consent refusal and audit-recovery state survive Livewire history writes. Delayed audit responses retain the notice captured at invocation and cannot revive permission after a newer refusal. Active withdrawal keeps its existing signals, declared-cookie cleanup, and required full reload.
- Partial application-owned Dutch dictionaries now inherit remaining Dutch package messages before English. Canonical service wording, saved-choice fingerprints, and expiry keep their existing translation rules.

## Upgrade

```bash
composer require "jakub-lipinski/consent-for-laravel:^1.5.0"
php artisan view:clear
```

Commit the application's Composer files and deploy with `composer install`. Preserve existing services, presets, IDs, policy version, cookie scopes, audit settings, colors, and custom wording. Rebuild relevant configuration/view/route caches and restart long-running workers.

**No new database migration, cookie migration, or automatic consent reset is required.** Applications without Livewire need no new frontend dependency or build. Older published configurations inherit these optional top-level defaults:

```php
'livewire' => [
    'enabled' => true,
    'navigation' => 'auto',
],
```

`auto` coordinates SPA visits; `reload` uses full visits. Boolean `enabled=false` disables special navigation/UI coordination. Generic fragment discovery and single-file inert-script protection remain. Keep one head and one banner in each participating shared layout and use stable explicit IDs for dynamic `@consent` blocks. Do not nest `@script`/`@assets` with `@consent`.

**Refresh customized head/banner views and all three published assets together:** `consent.js`, `banner.js`, and `consent.css`. Preserve the head's runtime-context marker and navigation attributes, the complete `data-consent-container` with its matching audit notice, full `wire:ignore`, presentation key, and locale/context attributes. Keep the UI bootstrap outside the protected container. Inline components use the installed sources directly. Clear compiled Blade/Livewire caches, invalidate stale page HTML, and cache-bust external assets.

Leave `ui.locale=null` and omit an explicit banner locale to follow the application's language. Set and preserve that locale before rendering pages and Livewire updates. Component/config locale overrides retain their priority. `cs-CZ` / `cs_CZ` fall back to Czech; `nl-NL` / `nl_NL` and `nl-BE` fall back to Dutch unless a more specific dictionary exists. Bundled translations work without publishing; preserve custom wording when merging application-owned dictionaries.

`@persist` is optional. Its layout-level wrapper must preserve the complete UI and notice outside Livewire components. A persisted app/config-locale interface uses a full refresh when the incoming locale differs. For other presentation changes, change the persist key or use normal remount. SPA visits cannot stop running tracker code, so active withdrawal retains its required full reload.

Test the application's actual CSP. Supply matching nonces to the consent components and Livewire. Livewire 4 needs its CSP-safe build when excluding `unsafe-eval`; nonce-bearing Livewire 3 uses full visits in auto mode. The initial document's CSP governs SPA destinations, and Livewire's DOMParser can need exact static-style hashes as well as nonces. The package does not loosen CSP or repair explicitly invalid script nonces.

Register any `consent:navigated` measurement listener once and use the existing guarded helpers. Review vendor-managed history/SPA settings to prevent duplicate views, especially GA4 enhanced history measurement. Denied measurements are discarded rather than replayed after acceptance.

Refresh selected Boost guidance and the complete skill with `php artisan boost:update`, preserving application overrides. No additional skill installation is needed. See the [Livewire guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.5.0/docs/livewire.md), [interface guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.5.0/docs/interface.md), [Boost guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.5.0/docs/boost.md), and [upgrade sequence](https://consent.lipinskijakub.pl/docs/upgrading#livewire-and-language-update) for complete integration details.
