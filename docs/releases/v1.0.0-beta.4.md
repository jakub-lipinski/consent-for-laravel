# v1.0.0-beta.4 - Google consent and measurement presets

These historical notes describe a prerelease. The installation command below uses the current stable package; archived prerelease tags predate its Composer vendor name.

The fourth development beta connects the existing preferences lifecycle to Google Consent Mode v2 and adds GA4 / Google Ads presets. Enable a preset, provide its ID, and keep the existing head/banner components. Basic blocks Google requests until permission; Advanced is an explicit configuration choice with a visible disclosure.

## Added

- Google Consent Mode v2 with denied optional defaults, restored state, and synchronous updates before change callbacks, activation, or reload.
- Basic mode by default and explicit Advanced mode for denied cookieless measurement, with English/Polish interface disclosure.
- GA4 and Google Ads presets registering their categories, purpose metadata, cleanup declarations, and initialization.
- One shared Google tag, the first allowed destination's ID in Basic, once-per-document destination configuration, and CSP nonce inheritance.
- `Consent.google.state()` and `Consent.google.event(destination, name, parameters)` with destination validation, initialization waiting, permission rechecks, and no replay of denied events.
- GA4 automatic page-view control for SPA owners and Ads conversion routing with an explicit registered ID and label.
- English/Polish default preset purposes, canonical overrides, and compatibility with explicit service-display translations.
- Strict serializable settings, ID validation, preset-service collision checks, and fingerprint invalidation for integration changes.

```php
// config/consent.php
'presets' => [
    'ga4' => [
        'enabled' => true,
        'measurement_id' => env('CONSENT_GA4_ID'),
        'send_page_view' => true,
    ],
    'google_ads' => [
        'enabled' => true,
        'conversion_id' => env('CONSENT_GOOGLE_ADS_ID'),
    ],
],
```

```javascript
await Consent.google.event('AW-123456789/YOUR_CONVERSION_LABEL', 'conversion', {
    transaction_id: 'order-123', value: 49.90, currency: 'PLN',
});
```

Replace example IDs/labels with your own. No duplicate vendor bootstrap or manual service definition is required.

## Changed

- Active built-in Google presets always reload on withdrawal, including when a custom hook requests cooperative cleanup. Denied signals and GA4's disable flag are applied before reload.
- Presets set ads data redaction, disable URL passthrough, and disable Google signals/ad personalization product features. Enabling a preset does not add enhanced conversions or user-provided data collection.
- A detected existing gtag, populated/non-array dataLayer, or Google bootstrap fails closed instead of establishing late consent defaults.
- Google loader failure reports a `google` diagnostic, leaves destinations unconfigured, and does not retry on the same document.

## Fixed

- External module `load` can occur before top-level await finishes. A nonce-bearing import marker now waits for the original module's evaluation after its SRI-checked load, keeping dependent script ordering and avoiding duplicate execution.
- Standalone browser test/demo pages remain outside the package, following the package-only scope cleanup after beta.3.

## Upgrade Notes

```bash
composer require jakub-lipinski/consent-for-laravel
php artisan vendor:publish --tag=consent-assets --force
php artisan config:cache
php artisan view:clear
```

- Merge `google` / `presets` into published configuration. All presets are disabled by default, so upgrading alone installs no tracker. No migration or new dependency is required.
- Supply IDs through configuration/environment values, enable only required services, remove old Google installs, and render the head before Google code.
- Review published banner views and translations for `google_advanced` and preset purpose strings. Preserve the disclosure if Advanced is enabled.
- Match declared cleanup domains/paths to actual cookies. Scope declarations do not configure Google's cookies or remove inaccessible third-party storage.
- Existing beta.3 cookie schema is unchanged. With no active bridge/presets, fingerprints remain compatible. Enabled target/ID/mode/init/purpose/scope changes make old decisions pending.
- Republish/cache-bust separate assets, merge customized views, and restart long-running host workers after configuration changes.
- Basic makes no Google requests before a grant. Explicit Advanced can send cookieless pings before a decision and after refusal. Assess and disclose the site's actual processing.
- GTM, Meta Pixel, and Microsoft Clarity remain future milestones. This is not Google CMP certification, a legal compliance certificate, or blanket host-site WCAG certification.

## Verification

- `composer check` passed locally on Laravel 13 / PHP 8.4: strict Composer validation, Pint, PHPStan, 199 PHP tests with 384 assertions, and 92 JavaScript tests.
- All 199 PHP tests also passed in four isolated installed dependency configurations: Laravel 12/13 highest dependencies on PHP 8.3 and lowest dependencies on PHP 8.4. These local runs are separate from the wider eight-combination GitHub Actions matrix.
- Native WebKit checks in a disposable host passed Basic pending/refusal/restoration, analytics-only and combined grants, one shared mock tag, guarded Ads conversion, denied-before-reload ordering, visible cookie cleanup, and explicit Advanced initialization/disclosure. No live Google property received measurements.
- External and inline modules waited for imports/top-level await in order. A correct SRI hash passed; an incorrect hash prevented both the external module and its dependent script while an independent block still ran, under a nonce CSP.
- The Polish Advanced banner/dialog fit 320 CSS pixels with 200% text and increased text spacing, without horizontal overflow. Keyboard wrapping kept focus inside the dialog, scrolled the final action into view, and restored the opener on Escape. Existing contrast and UI structural checks passed in the full suite.
- Actual Google account delivery, other engines, screen readers, OS high-contrast modes, and the entire host website are outside these local verification claims. See the [Google integration guide](../google.md) for setup, signals, event routing, cleanup, CSP, provider verification, and current primary references.
