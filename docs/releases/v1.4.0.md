# v1.4.0 - Matomo, TikTok Pixel, and Laravel Boost

This release adds **Matomo and TikTok Pixel presets** with guarded measurement APIs, plus **Laravel Boost guidelines and a development skill**. Matomo waits for analytics consent; TikTok waits for marketing consent. **Both presets are disabled by default**, and existing saved preferences remain compatible when their services and settings are unchanged.

## Added

- A Matomo preset for Cloud and self-hosted instances, with validated instance URLs and site IDs, automatic service registration, an initial page view, and outlink/download tracking after analytics consent.
- `Consent.matomo` helpers for events, goals, site searches, links, manual SPA page views, and e-commerce carts/orders. Each operation checks permission before dispatch, uses the configured tracker, and clears commerce items between operations. The application supplies business-event timing, product data, and totals; Matomo's website settings supply the currency.
- A TikTok Pixel preset with validated public Pixel IDs, automatic marketing service registration, and an initial page view. Loading waits for both the bootstrap and its second-stage runtime, then reapplies current consent before dispatch.
- `Consent.tiktok.track()`, `trackCustom()`, and `pageView()` for standard/custom events and application-managed SPA views. Event parameters are captured at invocation, and optional event IDs map to TikTok's `event_id` for a separately implemented browser/server deduplication strategy.
- Optional `Consent.tiktok.identify()` for Advanced Matching with application-prepared SHA-256 email, phone, and external-ID hashes. Raw identifiers are rejected. The helper does not collect fields, compute hashes, or install the Events API; hashing does not make identifying data anonymous.
- Translated Matomo and TikTok purpose descriptions in all seven bundled languages, with existing custom wording, regional fallback, theme, and variant behavior. Both integrations participate in signed audit notices and database decision history when auditing is enabled.
- Laravel Boost discovery through `resources/boost/guidelines/core.blade.php` and the `consent-for-laravel-development` skill. Twelve focused references cover setup, interface customization, custom scripts, browser/PHP APIs, audit history, every built-in integration, and verification.
- Self-contained skill references with configuration and event examples, provider-specific consent rules, common mistakes, and verification steps. Boost copies the skill and its references to selected agents and merges the short core into their guidelines; Boost remains an optional development dependency in the consuming application.

## Changed

- The ordered loader now initializes eligible Matomo and TikTok presets after Google, Meta, and Clarity, before custom Blade blocks. Ordinary SDK failures leave independent permitted work available; loading timeouts use the existing bounded reload recovery.
- Both new integrations discard measurements invoked without permission and cancel pending measurements on withdrawal. They do not replay denied events after a later acceptance. Helpers return local dispatch status, not proof of delivery or reporting in the vendor account.
- Active or in-flight Matomo/TikTok withdrawal signals denial before application change listeners, cleans declared first-party cookies, and requires reload. Matomo also disables link tracking and heartbeat timers. Protected session, CSRF, preference, and audit identity cookies remain protected.
- Matomo cookie scopes configure native cookies and cleanup; TikTok cookie scopes describe cleanup. Additional plugin cookies, former scopes, HttpOnly cookies, and unrelated third-party cookies still require appropriate owner handling.
- Documentation now covers both presets, their APIs, CSP, audit integration, and Boost installation/update/customization. The Boost Matomo reference explicitly distinguishes this preset's prior-consent model from separately assessed consent-exempt deployments.

## Upgrade

```bash
composer require "jakub-lipinski/consent-for-laravel:^1.4.0"
php artisan view:clear
```

Commit the application's Composer files and deploy with `composer install`. Preserve existing services, presets, IDs, policy version, cookie scopes, audit settings, and custom wording. Rebuild configuration/view caches and restart long-running workers.

**Existing configs work without the new entries and keep both presets disabled.** The preference cookie schema, unchanged service fingerprints, and existing decision lifetimes remain compatible. Enabling a new preset or changing its destination, canonical purpose, loading options, or cookie scopes changes the service fingerprint and requires a new decision.

To use either integration, merge the relevant entry into the application's existing `presets` section:

```php
'matomo' => [
    'enabled' => false,
    'url' => env('CONSENT_MATOMO_URL'),
    'site_id' => env('CONSENT_MATOMO_SITE_ID'),
    'send_page_view' => true,
    'enable_link_tracking' => true,
    'cookie_path' => '/',
    'cookie_domain' => null,
],
'tiktok_pixel' => [
    'enabled' => false,
    'pixel_id' => env('CONSENT_TIKTOK_PIXEL_ID'),
    'send_page_view' => true,
    'cookie_path' => '/',
    'cookie_domain' => null,
],
```

Set the actual instance URL/site ID or public Pixel ID in the application's environment, then enable only the requested preset. The Matomo URL is the instance base URL, including any subdirectory, rather than `matomo.js` or `matomo.php`. No manual service or SDK snippet is needed; remove duplicate tracker installations and tag-manager entries first. Keep the head and banner components in the shared layout.

Refresh/cache-bust published `consent.js` before enabling the new presets. An old runtime cannot handle their configuration. Inline components use the installed sources directly. This release does not change the banner view, `banner.js`, or `consent.css`; merge them too when skipping an earlier release that changed them. Merge the new purpose descriptions into application-owned translation dictionaries where appropriate. Bundled translations work without publishing.

**The Matomo preset always requires analytics consent.** It does not provide a cookieless baseline or consent-exempt mode. A separately assessed exempt deployment needs its own configuration and any required opt-out, with this preset disabled. TikTok always requires marketing consent, including when Google Advanced is selected. Review provider/account settings for overlapping automatic events or SPA measurements, and test the actual CSP and cookie scopes.

For AI assistance, install Boost in the development application if needed:

```bash
composer require laravel/boost --dev
php artisan boost:install
```

Select **AI Guidelines**, **Agent Skills**, `jakub-lipinski/consent-for-laravel`, and the agents you use. Existing Boost installations can discover the new package resources with `php artisan boost:update --discover`; subsequent `boost:update` runs refresh the selected guidance and skills. Preserve application customizations through Boost's custom guideline/skill mechanisms rather than editing generated copies or `vendor` files. Installing these resources does not enable tracking or change visitor decisions.

See the [Matomo guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.4.0/docs/matomo.md), [TikTok guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.4.0/docs/tiktok.md), and [Boost guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.4.0/docs/boost.md) for complete configuration, measurement examples, withdrawal, CSP, and generated files.
