# v1.0.0 - Cookie consent for Laravel

The first stable release brings the complete consent lifecycle to PHP 8.3+ and Laravel 12-13: configurable banners, purpose-based preferences, cache-safe script gating, and ID-based Google, Meta and Microsoft integrations.

## Included

- Five standard categories: necessary, analytics, marketing, performance, and other. Preferences show only used optional categories.
- A service registry, application-owned policy version, integration fingerprints, strict cookie validation, configurable retention, and stateless PHP reads. Missing, expired, refused, or incompatible decisions grant no optional permission.
- `@consent('category', 'stable-id')` inert Blade blocks with ordered loading, duplicate prevention, permission rechecks, CSP nonce propagation, modules/imports/top-level-await support, and bounded loader/cleanup timeouts.
- Bottom-left, bottom-right, and wide bottom-center banners; a native preferences dialog; a reopening icon; a configurable policy link; validated colors; and English/Polish messages and preset purposes.
- Native controls, managed focus, keyboard wrapping, Escape handling, responsive reflow, equal acceptance/refusal prominence, and protection against obscuring focused host controls.
- Google Consent Mode v2 with denied defaults and ordered updates. Basic blocks Google requests before permission; explicit Advanced permits cookieless pings while denied.
- GA4 and Google Ads presets with shared gtag.js loading, ID validation, PageView control, guarded events, explicit conversion labels, and scoped first-party cookie cleanup.
- Meta Pixel with marketing gating, revoked defaults, optional PageView, standard/custom events, and optional event IDs.
- Microsoft Clarity with analytics gating, Consent API v2, custom events, and separately enabled advertising requiring both analytics and marketing permission.
- Mandatory reload after active preset withdrawal, denial before listeners/cleanup, declared visible cookie deletion, and protection of preference, session, CSRF, and remember-me cookies.

```bash
composer require jakub-lipinski/consent-for-laravel
php artisan vendor:publish --tag=consent-config
```

The stable package is available directly from [Packagist](https://packagist.org/packages/jakub-lipinski/consent-for-laravel). Run these in your Laravel application; no VCS entry or minimum-stability change is needed. Follow [the current quick start](../../README.md#quick-start-with-ga4) for preset setup. The custom script below is a placeholder supplied by your own application.

```blade
<head>
    <x-consent::head />
</head>

<x-consent::banner />

@consent('analytics', 'site-insights')
    <script src="/js/site-insights.js"></script>
@endconsent
```

Register custom processing purposes in `consent.services`, or enable a preset with your actual provider ID. Presets remain disabled by default and register their own purposes. No database, migration, frontend framework, npm build, application route, dashboard, or standalone website is installed.

## Changed

- The Composer package name is `jakub-lipinski/consent-for-laravel`, matching the GitHub publisher.
- The documented PHP, Blade, browser, and configuration APIs form the stable version 1 series.
- Current guides and the separate documentation website describe implemented capabilities, with standard Composer installation and no development milestones or future integration promises.
- Exported archives exclude package-development npm manifests and locks, along with tests and development configuration.

## Fixed

- Google events now check permission at invocation, so events requested before a queued grant are discarded rather than replayed. JSON parameters are captured immediately and permission is rechecked before dispatch.
- A failing Google command queue cannot prevent active consent withdrawal, cookie cleanup, or mandatory reload. Failures emit a Google diagnostic and block further preset events.
- Preference cookie names starting with `remember_` are rejected, preventing the consent provider from exempting Laravel remember-me cookies from encryption.

## Upgrade Notes

```bash
composer require "jakub-lipinski/consent-for-laravel:^1.0"
php artisan config:cache
php artisan view:clear
```

Use `php artisan config:clear` locally; the cache command above is for production deployment. If using separately published assets, preserve application customizations before running `php artisan vendor:publish --tag=consent-assets --force`. For earlier VCS installs, follow [switching to Packagist](../../README.md#switching-from-vcs).

- Cookie schema 1 and unchanged service fingerprints remain compatible with the previous release. Changing actual processing metadata or the policy version still requires a fresh decision.
- Merge published configuration, views, and translations deliberately. Republish and cache-bust separate assets if used; restart persistent application workers. Inline default components use the installed sources directly.
- Keep preference cookie names separate from session/CSRF cookies and the `remember_` prefix. Clean up any old preference cookie using its original path/domain when changing scope or name.
- Remove duplicate vendor bootstraps before enabling presets. Enable Require cookie consent and review masking in Clarity; review Meta and Google account processing settings separately.
- The package supplies consent tooling and an interface targeting applicable WCAG 2.2 A/AA criteria. It does not certify whole-site accessibility, legal compliance, provider approval, or live account delivery. Cookie preferences are unsigned, user-editable, and never authentication or an identity audit trail.
