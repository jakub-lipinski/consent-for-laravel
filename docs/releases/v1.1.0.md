# v1.1.0 - Standard and Compact interfaces

Choose one appearance for the cookie banner and its preferences dialog. Standard preserves the original interface; Compact provides a smaller, simpler presentation with the same consent controls and complete purpose information.

## Added

- `consent.ui.variant`: `standard` (default) or `compact`. Unknown values and non-string settings are rejected.
- `<x-consent::banner variant="compact" />` overrides the configured variant for both the banner and its native preferences dialog.
- Compact uses smaller cards/dialogs, less padding and category/service spacing, simpler corners, and equally prominent outlined acceptance/refusal buttons. Wider cards place acceptance/refusal side by side; small screens stack actions.
- Category purposes remain visible. Complete service lists use native, keyboard-accessible disclosures in Compact; Standard preserves the original expanded lists. Expanding service information never changes consent.
- Both variants support every banner position, validated colors, English/Polish wording, registered service details, draft cancellation, keyboard focus handling, saving, reopening, and withdrawal.

```php
'ui' => [
    'variant' => 'compact',
    'position' => 'bottom-left',
    'locale' => null,
    'policy_url' => '/cookies',
    'colors' => [],
],
```

## Upgrade from 1.0

Policy links and action buttons also reset inherited host-page spacing, keeping their left edges aligned with the interface text in both variants.

```bash
composer config repositories.consent vcs https://github.com/jakub-lipinski/consent-for-laravel.git
composer require jakub-lipinski/consent-for-laravel:^1.1
php artisan config:cache
php artisan view:clear
```

Register the official VCS source once when installing from GitHub; Packagist does not currently index the package. Composer resolves the stable tag without reducing minimum stability.

Existing published configurations without `ui.variant` keep Standard. Add the new setting when selecting Compact. Inline components use the installed sources; customized published views must incorporate the `variant` prop and `data-consent-variant` root attribute. Merge view changes deliberately, retaining existing customizations and bindings.

If serving published assets separately, republish them with `php artisan vendor:publish --tag=consent-assets --force`, update asset URLs to invalidate caches, and restart persistent application workers. Updated styles and views must be deployed together for Compact to apply to both interfaces. No new translation keys are required.

The cookie schema, service fingerprints, purpose descriptions, retention, runtime APIs, and tracker gates remain compatible. Changing variant does not invalidate, renew, or otherwise modify a saved grant or refusal. Standard is the backward-compatible default. Custom CSS and published views still need integration accessibility checks.
