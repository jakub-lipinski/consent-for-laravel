# v1.1.3 - Non-blocking theme diagnostics

A custom accent such as `#d86a32` previously threw an exception during banner rendering when its contrast was below the configured threshold. That exception could turn the entire host response into HTTP 500. Theme contrast now uses optional, non-blocking diagnostics.

## Behavior

- `ui.validate_contrast` defaults to `false`, including when absent from existing published configuration.
- Setting it to `true` logs warnings for the existing contrast thresholds and preserves the chosen colors. It does not throw or replace a syntactically valid theme.
- Invalid color formats use the corresponding default. Unknown color keys are ignored; a malformed colors array uses the default palette. Format issues log a warning independently of contrast diagnostics. Unsafe values never enter CSS.
- Diagnostics logger failures cannot interrupt rendering. Consent policy, services, cookies, tracker gates, and saved-decision lifetimes are unaffected.
- The default palette continues to meet the tested contrast thresholds. Accepted custom colors still need an accessibility review.

## Upgrade

```bash
composer require "jakub-lipinski/consent-for-laravel:^1.1.3"
```

Commit the application's Composer files and deploy with `composer install`. Rebuild application configuration/view caches and restart persistent workers. No browser asset, view, translation, cookie schema, or decision migration is required. Add the optional boolean to published configuration only if you want diagnostics:

```php
'ui' => [
    // Existing UI settings and colors...
    'validate_contrast' => true,
],
```

## Verification

- `composer check` passed Composer validation, Pint, PHPStan level 8, 259 PHP tests / 575 assertions, JavaScript syntax checks, and 132 JavaScript tests.
- Regression requests with the reported orange theme return HTTP 200 with the new key absent, false, or true. Unsafe colors, malformed palettes, logger failure, and saved-consent compatibility are covered.
- Focused theme/banner/configuration tests passed 112 cases / 288 assertions in four cached PHP 8.3/8.4 and Laravel 12/13 dependency sets. The older Laravel 12 / PHP 8.4 set also reported dependency deprecations; assertions passed. These are locally executed compatibility sets, not newly resolved global dependency minima/maxima.
- A disposable native-browser host outside the package verified both variants, diagnostics on/off, nonce CSP, preferences, draft versus saved choices, gated script activation, withdrawal/reload, invalid-color fallback, and an unavailable logger. No browser console errors were observed.
- Custom low-contrast colors are intentionally preserved; this verification does not certify their accessibility or whole-site conformance.
