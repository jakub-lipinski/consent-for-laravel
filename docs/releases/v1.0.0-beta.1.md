# v1.0.0-beta.1 - Versioned consent foundation

This first beta adds the PHP foundation for service-based consent preferences. Applications can describe their services, record a category selection, and restore a current decision from a first-party cookie. Acceptance and refusal are remembered equally, without extending decisions during ordinary page visits.

## Added

- A validated service registry with stable IDs, names, purpose descriptions, and enabled flags.
- Necessary, analytics, marketing, performance, and other categories, with only used optional categories exposed.
- Immutable consent decisions and `ConsentManager` methods for reading, choosing, accepting, rejecting, persisting, and forgetting preferences.
- A versioned JSON cookie containing schema, policy, service fingerprint, choices, decision time, and expiry.
- Automatic invalidation for changed active services or policies, expiry, and invalid stored values.
- Configurable retention and cookie scope, with a 180-day default shared by acceptance and refusal.
- Middleware integration that leaves session and CSRF cookies encrypted, plus private, non-cacheable persistence responses.
- Integration tests for decision transitions, expiry boundaries, malformed values, configuration, and HTTP cookie round trips.

```php
use ConsentForLaravel\ConsentForLaravel\ConsentManager;

$consent = app(ConsentManager::class);
$decision = $consent->choose(['analytics' => true]);

return $consent->persist($decision, response()->noContent(), $request);
```

## Changed

- Replaced the empty skeleton configuration with implemented service, policy, retention, and cookie settings.
- Added explicit HTTP and cookie dependencies and documented the public PHP API.

## Upgrade Notes

- This is a development beta. Banner UI, `@consent`, browser script blocking, Google Consent Mode v2, and tracker presets are not included yet.
- If upgrading from the initial skeleton, republish `consent-config` and review the new options before rebuilding the application configuration cache.
- Register actual processing purposes before recording decisions. The registry describes services but does not initialize them.
- Call decision methods only after an explicit user action and keep application endpoints CSRF-protected.
- The preference cookie is browser-readable and unsigned. It is not an authentication mechanism or a database record proving consent.
- This beta does not claim EU legal compliance or WCAG conformance. The complete interface and integrations are scheduled for subsequent betas.
