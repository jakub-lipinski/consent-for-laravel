# v1.5.2 - Navigation fixes and inherited themes

This update fixes **TikTok startup across Livewire visits**, **Blade expressions in gated Livewire 4 scripts**, and **retained DOM from removed pages**. The new `inherit` theme follows the website's own color scheme. **Existing APIs and saved preferences remain compatible.**

## Added

- Set `ui.theme` to `inherit` to select the configured light or dark palette using the nearest ancestor's CSS `color-scheme`. Both interface variants follow live changes, including an open preferences dialog, without theme JavaScript, additional storage, or a consent update. An unspecified host scheme or a browser without CSS `light-dark()` support uses the light palette. The existing `light`, `dark`, and `auto` modes keep their behavior, including application CSS overrides.

## Fixed

- TikTok's two-stage SDK readiness wait survives a temporary Livewire navigation pause. Readiness can finish before, during, or after the swap; initialization resumes once after a compatible destination and a current marketing grant. Calls made during navigation remain discarded. Withdrawal, expiry, incompatible context, genuine SDK failures, and bounded waits for an unready SDK still stop activation.
- Gated Livewire 4 single-file and multi-file scripts preserve Blade/PHP expressions containing script-like literals through preparation and normal Blade compilation. Serialized values containing `</script>` or `@endconsent` no longer break the extraction boundary. Existing Blade escaping and browser consent gates retain their behavior.
- Document-lifetime block records no longer keep detached templates and old page bodies alive. Private execution copies are retained only while a chain needs them, and removed script-node references are released. Stable identities, external-source deduplication, and active revocation history remain available after collection. Waiting identical replacements can still activate; detached started chains cannot resume their tails.

## Upgrade

```bash
composer require "jakub-lipinski/consent-for-laravel:^1.5.2"
php artisan view:clear
```

Commit the application's Composer files and deploy with `composer install`. Preserve existing services, presets, policy version, cookie scopes, audit settings, palettes, and custom wording. Rebuild relevant deployment caches and restart persistent workers. Livewire 4 also clears its compiled component files through `view:clear`.

**No migration, policy-version change, or consent reset is required.** The preference cookie schema, unchanged service fingerprints, and original decision lifetimes remain compatible. Older published configurations keep the light theme by default; `inherit` is optional.

Refresh/cache-bust published **`consent.js` and `consent.css`**, preserving application customizations. Inline components use the installed sources. Clear stale compiled views and cached HTML so the updated PHP preparation hook and runtime are used. From v1.5.1, the head/banner markup, `banner.js`, and translations do not require an update. Apply the relevant earlier upgrade steps when skipping releases.

To follow an application-owned theme switch, set `theme` to `inherit` inside the existing `ui` section and set `color-scheme: light` or `dark` in the host's corresponding CSS rules. A class or data attribute alone does not declare a color scheme. Inherit selects the existing `colors` and `dark_colors`; it does not copy host colors. See [the theme guide](https://consent.lipinskijakub.pl/docs/banner-and-theme#follow-the-website-theme).

Refresh selected Boost resources with `php artisan boost:update`, preserving application overrides. The existing interface, Livewire, TikTok, and verification references cover this update; no additional skill or reference is needed.

See [the upgrade sequence](https://consent.lipinskijakub.pl/docs/upgrading#navigation-fixes-and-inherited-themes) for deployment and host-application checks.
