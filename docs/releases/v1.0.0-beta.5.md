# v1.0.0-beta.5 - Meta Pixel and Microsoft Clarity

This beta adds ID-based Meta Pixel and Microsoft Clarity presets with strict consent gates, guarded events, English/Polish purposes, and provider-specific withdrawal. The existing Google integrations remain available. GTM is deferred, so the additional presets ship as beta.5 instead of the previously planned beta.6.

## Added

- Meta Pixel setup through `presets.meta_pixel`, with a marketing purpose, vendor-compatible queue, revoked defaults, once-per-document initialization, and optional automatic PageView.
- `Consent.meta.track()` and `Consent.meta.trackCustom()` with JSON parameter capture, optional `eventID`, initialization waiting, permission checks at invocation/dispatch, and no replay of denied calls.
- Microsoft Clarity setup through `presets.clarity`, with an analytics purpose and Consent API v2 using the exact `analytics_Storage` / `ad_Storage` keys.
- Clarity advertising disabled by default. Explicit enablement adds a separate marketing purpose and requires both analytics and marketing permission before granting ad storage.
- `Consent.clarity.event()` for guarded custom events and `Consent.clarity.state()` for immutable signal inspection without loading an SDK.
- Optional canonical purpose overrides, scoped `_fbp`/`_fbc` and `_clck`/`_clsk` cleanup, and English/Polish preset wording.
- Strict serializable settings, ID/boolean validation, disabled-definition validation, reserved service collision checks, and fingerprints covering integration behavior.

```php
// config/consent.php
'presets' => [
    'meta_pixel' => [
        'enabled' => true,
        'pixel_id' => env('CONSENT_META_PIXEL_ID'),
        'send_page_view' => true,
    ],
    'clarity' => [
        'enabled' => true,
        'project_id' => env('CONSENT_CLARITY_ID'),
        'advertising' => false,
    ],
],
```

```javascript
await Consent.meta.track('Purchase', { value: 49.90, currency: 'PLN' }, { eventID: 'order-123' });
await Consent.meta.trackCustom('NewsletterSignup');
await Consent.clarity.event('checkout-completed');
```

Use your own IDs, retain other preset settings when needed, and render the existing head/banner components. No separate bootstrap, manual service, or Blade gate is needed for an enabled preset.

## Changed

- Active Meta/Clarity withdrawal signals denial before listeners and requires reload, including Clarity advertising withdrawal while analytics remains granted or the library is in flight. Cooperative custom hooks cannot suppress preset reloads.
- Both libraries stay unloaded without their required category, independently of Google Advanced. There is no Meta noscript tracking image or pre-consent Clarity cookieless mode in the package.
- Existing tracker globals/bootstrap scripts fail closed before package activation. Ordinary provider errors are isolated and do not retry; shared-loader timeouts require a fresh document and stop further activation.
- The roadmap now places integrated verification and release preparation at beta.6. GTM has no assigned beta.

## Upgrade Notes

```bash
composer require webcrafts-studio/consent-for-laravel:1.0.0-beta.5
php artisan vendor:publish --tag=consent-assets --force
php artisan config:cache
php artisan view:clear
```

- Merge the new preset settings and the three English/Polish `messages.presets` entries into published files. Customize views deliberately; republish and cache-bust external assets when used. Restart persistent host workers.
- All presets remain disabled by default. Enabling them requires valid string IDs. Remove duplicate snippets, noscript pixels, tag-manager installs, and colliding manual services.
- Reserved IDs are `meta-pixel`, `microsoft-clarity`, and optionally `microsoft-clarity-ads`. Clarity also accepts `advertising_name` / `advertising_description` for its separate marketing purpose.
- Enable Require cookie consent in your Clarity project, review masking, and keep sensitive data out of recordings, URLs, and event parameters. Review Meta product settings separately.
- Scope declarations describe cookie deletion, not vendor cookie creation. Match real paths/domains, including parent-domain cookies. Third-party, HttpOnly, and historical remote data are outside local cleanup.
- The cookie schema is unchanged. With the new presets disabled, beta.4 fingerprints remain compatible, including Google-only installations. Enabling or changing identifiers/options/purposes/scopes makes old decisions pending.
- Clarity's denied storage mode is not a complete tracking-stop API. The package gates loading and reloads active withdrawal; previously transmitted or in-flight data cannot be recalled.
- No new dependency, migration, dashboard, standalone website, Conversions API integration, or vendor certification is added. See the [tracker guide](../tracker-presets.md) for setup, SPA events, lifecycle, and primary references.
