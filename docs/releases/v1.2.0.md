# v1.2.0 - More languages, dark mode, and quieter diagnostics

This release adds **seven bundled languages**, custom locale fallback, and **light/dark/auto themes** for both Standard and Compact. Theme warnings are limited to one logging attempt per identical palette/issue group every **72 hours**. Existing configurations keep the light default, and presentation changes preserve saved consent decisions and their original expiry.

## Added

- German, French, Italian, Spanish, and European Portuguese join English and Polish. All seven dictionaries include interface copy, accessible labels, category purposes, preset descriptions, and the Advanced Google notice.
- Custom languages no longer require a package language allowlist. Add `lang/vendor/consent/{locale}/messages.php` and optional `services.php` directly in the consuming application, then select the locale through the banner component, config, or app.
- Partial dictionaries inherit missing or blank keys from regional/script parents and then English. For example, `fr-CA` falls back through `fr` to `en`. Hyphen and underscore directories are supported; valid locales without dictionaries safely render English. Malformed explicit tags and non-string messages remain errors.
- Configuration-only `ui.theme` accepts `light`, `dark`, or `auto`. Both variants theme the banner, preferences dialog, fallback, and launcher. Auto follows CSS `prefers-color-scheme`, including live changes, without a visitor-facing switch or theme cookie.
- Independent `ui.colors` and `ui.dark_colors` overrides retain empty-array defaults. Missing entries inherit the corresponding palette; custom light colors are not automatically inverted. Both default palettes meet the package's contrast thresholds.

## Fixed

- Identical theme warnings no longer log on every request when the application's default cache retains the suppression marker. Both resolved palettes and the issue list define the group; changing a palette or issue allows an immediate new attempt.
- The interval is claimed with atomic cache `add` before logging. Theme mode, variant, locale, position, policy URL, equivalent HEX casing, and color-key ordering do not restart it. Repeated reads do not extend the 72-hour window.
- Cache failures skip optional logging instead of flooding logs or breaking rendering. Logger failures preserve rendering and retain the claimed interval. A persistent file, Redis, or database cache suppresses across requests; `array` only retains markers during its lifetime, while `null` skips these diagnostics.
- Contrast checks cover both palettes, including an inactive dark palette, and identify light/dark in each issue. Valid selected colors remain unchanged; invalid values fall back to their palette defaults and never enter CSS.

## Changed

- The published config uses Laravel-style comment sections, supported values, and commented color/service examples without changing existing defaults.
- README is shorter and links to the complete documentation website. The guides cover custom dictionaries, independent palettes, warning suppression, and upgrades.
- Service display translations use the requested locale even when UI text falls back to a parent language. Customized canonical preset wording remains intact unless explicitly overridden by service display translations.
- Theme selection is resolved in scoped CSS with matching native control and scrollbar colors. It does not change the host page's theme, activate scripts, reset an open draft, or write a consent decision. The launcher focus outline has backing in its own background color for opposite-themed host pages.

## Upgrade

```bash
composer require "jakub-lipinski/consent-for-laravel:^1.2.0"
php artisan view:clear
```

Commit the application's Composer files and deploy with `composer install`. Rebuild configuration caches after merging settings and restart long-running workers. Keep your actual services, presets, IDs, policy version, cookie scopes, and custom wording.

Merge these options into the existing `ui` section when using theme selection:

```php
'ui' => [
    // Existing UI settings...
    'theme' => 'auto', // light, dark, or auto
    'colors' => [],
    'dark_colors' => [],
],
```

**Existing configs work without the new keys and keep light.** Preserve existing light color overrides; choose dark brand colors independently. There is no new Blade theme prop. Nonce-protected inline palette overrides can still be required when the main CSS is published externally.

Update customized banner views with `data-consent-theme` and both-palette override logic, preserving control bindings and nonces. Refresh/cache-bust published `consent.css` together with the views. This release does not change `consent.js` or `banner.js`; update them too when skipping an earlier release that changed them. Inline components use the installed sources directly.

Bundled languages work without publishing. Merge application-owned dictionaries deliberately, or add custom files directly. Display translations and themes do not change the cookie schema, unchanged service fingerprints, saved grants/refusals, or expiry. A real purpose change still requires updated canonical metadata or the application-owned policy version.

Warning suppression uses the current default cache and adds no table, migration, store, or visitor identifier. Clearing or evicting markers can permit earlier attempts. Check that the chosen cache supports persistent atomic `add` if suppression across requests is required. Custom RTL dictionaries also need view/layout adaptation and browser verification.

See the [theme guide](https://consent.lipinskijakub.pl/docs/banner-and-theme), [translation guide](https://consent.lipinskijakub.pl/docs/translations), and [upgrade steps](https://consent.lipinskijakub.pl/docs/upgrading#language-and-theme-update).

## Verification

- Local `composer check` passed strict Composer validation, Pint, PHPStan level 8, **362 PHP tests / 1999 assertions**, JavaScript syntax checks, and **148 JavaScript tests** on PHP 8.4.25 / Laravel 13.35.0 / Node 22.21.1.
- Focused regressions cover seven dictionaries in both variants, partial/custom/regional fallback, preserved canonical wording, config caching, independent palettes, unsafe colors, nonce-protected overrides, unchanged consent gates/lifetimes, and the exact 72-hour boundary. File-cache checks verify persistence across independent repositories and safe rendering with unavailable cache/logging.
- A disposable native-browser host outside the package checked both variants, all seven languages, custom Dutch and Canadian French dictionaries, keyboard modality, focus return, expanded service disclosures, and gated module ordering under nonce CSP. Reflow checks covered 320px, 200% text sizing, increased spacing, and all three positions.
- Both variants rendered light, dark, and auto with no full-axe violations in tested banner/modal states. Dark French layouts passed the same reflow and keyboard checks. Auto branches were exercised by a host-only CSS media-rule harness and preserved an open draft; the browser's actual preference was light, so an actual OS preference toggle is not claimed.
- Closed-dialog reference checks remained incomplete in axe and were reviewed manually. The host had no CSP violations at DOM readiness; later browser instrumentation produced a blocked anonymous inline-style event, so a clean console is not claimed.
- Local checks are distinct from the configured eight PHP 8.3/8.4 and Laravel 12/13 lowest/highest CI combinations. Other browser engines, screen readers, forced-colors modes, arbitrary custom/RTL layouts, live vendor delivery, and whole-site legal/accessibility certification are not claimed. See [detailed interface verification](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.2.0/docs/interface.md#verification).
