# v1.4.1 - Bug fixes and runtime stability

This patch fixes five defects found during integration testing, improving **script gating**, **ordered loading**, and **audited consent changes**. Save-failure messages now describe the failed operation without making incorrect claims about existing permissions. **Existing APIs and saved preferences remain compatible.**

## Fixed

- A discovered consent block can no longer execute changed scripts under its original category. Changes to its ID, category, or content stop its remaining chain with a conflict diagnostic, including mutations while an external script is loading. Private script snapshots prevent changed node references from bypassing the guard after identical markup is restored.
- A mixed audited change, such as withdrawing analytics while allowing marketing, no longer loses the new grant when active withdrawal reloads the page. Withdrawal still applies immediately. The next document retries the same event UUID and original signed notice, then activates the new category only after a matching durable receipt. A newer choice, changed saved decision, failed receipt, or expired handoff prevents recovery from restoring permission.
- Waiting blocks now start in **current document order**, including fragments prepended or moved after discovery and changes made during an earlier asynchronous load. The running block retains its internal dependency order, and a denied category does not delay an independent allowed block.
- Detached waiting templates no longer fetch or execute their scripts. Detaching an active template prevents its remaining scripts from starting; code already running or loading still requires the existing cleanup/reload lifecycle. Identical replacements of unstarted blocks retain their stable identity, while started blocks preserve deduplication and revocation history after removal.
- Save-failure text is corrected in **all seven bundled languages** and both interface variants. An unavailable audit endpoint can preserve a valid analytics grant while rejecting new marketing permission; the alert now reports the failed save and invites a retry instead of claiming that every optional cookie is blocked or suggesting an unverified cookie-storage problem.

## Upgrade

```bash
composer require "jakub-lipinski/consent-for-laravel:^1.4.1"
php artisan view:clear
```

Commit the application's Composer files and deploy with `composer install`. Preserve existing services, presets, policy version, cookie scopes, audit settings, and custom wording. Rebuild relevant configuration/view caches and restart long-running workers.

**No API changes, new configuration keys, database migrations, or consent reset are required.** The preference cookie schema, unchanged service fingerprints, and existing decision lifetimes remain compatible.

Inline components automatically use the installed sources. If serving published assets, refresh/cache-bust `consent.js`, preserving application customizations. The banner markup, `banner.js`, and CSS are unchanged from v1.4.0. Clear cached HTML so it uses the updated runtime and translated error text.

For application-owned or published translation dictionaries, merge the updated `save_failed` message while preserving custom wording. Bundled dictionaries work without publishing. The English message is now: "Your preferences could not be saved. Please try again."

SPA integrations must keep each discovered block's ID, category, and content unchanged. Use a distinct stable ID for a different logical block; retain the same ID and content when rendering the same block again. This existing identity contract is now enforced during loading as well as discovery.

Audited recovery uses a short-lived same-tab handoff in session storage, with an object-valued history-state fallback. If neither can retain the handoff, withdrawal still takes effect and the new grant fails. This recovery is bounded and does not provide an offline queue. Ordinary decisions without a required reload retain their existing storage behavior.

See the [browser runtime guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.4.1/docs/browser-runtime.md), [audit log guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.4.1/docs/audit-log.md), and [interface guide](https://github.com/jakub-lipinski/consent-for-laravel/blob/v1.4.1/docs/interface.md) for block identity, recovery, and error behavior.

- **46 new JavaScript regressions** cover mutation guards, private snapshots, audited reload recovery, superseded choices, storage fallbacks, failed receipts, dynamic block ordering, detachment/replacement, cross-document adoption, and retryable translated alerts.

- Mixed audited choices were verified with actual SQLite writes and a held receipt across reload: the original event was retried without duplicate rows, new grants waited for acknowledgement, and browser choices matched the stored decision.
- Standard and Compact passed **14 native error/retry scenarios** across all seven languages at 320 CSS pixels and 200% text sizing. Earlier analytics remained allowed after simulated HTTP 503, marketing remained denied, keyboard modality and reflow were preserved, and retry successfully saved the new permission.
- These locally executed checks are distinct from the configured eight PHP 8.3/8.4 and Laravel 12/13 lowest/highest CI combinations.
